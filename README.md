# AnalyticsBot

Сервис собирает показатели постов Telegram-каналов через 24 часа и записывает их в существующие Google-таблицы. Задания и снимки хранятся в SQLite, альбом считается одним постом. Python 3.11+.

## Windows-приложение

Готовую папку `AnalyticsBot` из `gui-dist` можно перенести на другой Windows-компьютер. Запустите `AnalyticsBot.exe`; устанавливать Python на том компьютере не нужно. Поместите папку в доступное для записи место, например в «Документы». Приложение создаст рядом с `.exe` папку `user_data` с настройками, SQLite-базой, Telegram-сессией и копией выбранного JSON-ключа. При переносе на другой компьютер закрывайте приложение и переносите всю папку вместе с `user_data`. Для распространения новой копии **без ваших данных** передавайте папку без `user_data`.

При первом запуске откройте «Настройки», укажите полученные на https://my.telegram.org `API ID` и `API hash`, войдите по номеру и коду или по QR-коду. При включённой двухэтапной защите введите её пароль. В Google Cloud включите Sheets API, создайте сервисный аккаунт и скачайте JSON-ключ. В приложении выберите его, а в Google Sheets откройте нужную таблицу для `client_email` из ключа с правом редактора. На странице «Каналы» добавьте ссылку на канал, ссылку на таблицу, название вкладки и при необходимости настройте буквы столбцов. Для приватного канала сначала вступите в него нужным аккаунтом. Проверки подключения Telegram и конкретной Google-таблицы доступны в настройках.

На главной странице запустите сервис. Перед изменением каналов или авторизации остановите его. На странице «Каналы» можно выбрать канал и дозагрузить последние посты старше 24 часов; на время дозагрузки основной сбор должен быть остановлен. Закрытие окна сворачивает приложение в системный трей; через значок можно открыть окно или полностью завершить программу. В настройках можно включить запуск приложения при входе в Windows и отдельно — автоматический запуск сбора. Если папка программы перемещена, заново включите автозапуск, чтобы обновить путь Windows.

Для переноса существующей установки CLI до заполнения новых настроек нажмите «Импортировать данные существующего сервиса» на странице настроек и выберите папку проекта с `config.yaml` и `.env`. Сначала остановите старый сервис. Приложение скопирует настройки, ключ Google, базу и сессию, не изменяя оригиналы. Импорт разрешён только в пустую папку данных GUI. После импорта не запускайте старый CLI и GUI одновременно: у них независимые базы и копия одной Telegram-сессии, что может вызвать конфликты и дубли. По умолчанию GUI и CLI используют разные файлы и не синхронизируют изменения.

Для сборки на Windows с установленным Python:

```powershell
.venv\Scripts\python -m pip install -r requirements-gui.txt
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

Результат — `gui-dist\AnalyticsBot\AnalyticsBot.exe` вместе с папкой зависимостей `_internal`. Скрипт не добавляет `.env`, `config.yaml`, ключи, базы или сессии в сборку и отказывается перезаписывать результат, если рядом с ним уже есть `user_data`: сохраните эту папку отдельно перед пересборкой. Сборку нужно выполнять на Windows.

## Запуск без интерфейса

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
Copy-Item config.example.yaml config.yaml
```

Получите `api_id` и `api_hash` на https://my.telegram.org, заполните `.env`. В Google Cloud включите Sheets API, создайте service account и сохраните JSON-ключ; откройте таблицу для `client_email` из ключа с правом редактирования. В `config.yaml` укажите каналы, ID таблицы, имя листа и столбцы.

```powershell
.venv\Scripts\python -m analyticsbot --login-qr
.venv\Scripts\python -m analyticsbot
```

Для QR-входа откройте в Telegram «Настройки → Устройства → Подключить устройство». Можно также использовать `--login` для входа по номеру и коду. Сессия сохраняется в `data/`; храните её, базу SQLite и JSON-ключ в безопасности. Для непрерывной работы оставьте процесс запущенным или настройте его запуск через системный планировщик.

## Дозагрузка последних постов

Остановите работающий сервис через `Ctrl+C` и выполните, например:

```powershell
.venv\Scripts\python -m analyticsbot --channel "@example_channel" --last 10
```

Канал должен быть указан в `config.yaml`. Команда рассматривает последние 10 постов этого канала, которым уже исполнилось 24 часа, включая альбомы как один пост, и записывает недостающие строки в его настроенный лист. Более свежие публикации остаются для обычного сбора через 24 часа. Посты, уже имеющиеся в таблице, пропускаются; количество не увеличивается для замены пропущенных дублей. Для ранее обработанного поста, строку которого удалили, используется сохранённый снимок, если он есть. Обычный курсор истории не меняется.

При ручной дозагрузке постов старше 24 часов показатели собираются в момент запуска команды, если снимок ещё не сохранён. Если отправка завершилась ошибкой, задание останется в SQLite и повторится при работе сервиса. После команды снова запустите `.venv\Scripts\python -m analyticsbot`.

## Таблица

При запуске сервис оформляет первую строку листа, закрепляет её и устанавливает ширину столбцов. Видимые поля: дата, название поста со ссылкой, просмотры, реакции, репосты, комментарии, подписчики, ER и ERR. Название — начало текста поста; если текста нет, используется номер поста. Дата отображается в часовом поясе `sheet.timezone` (по умолчанию `Europe/Moscow`).

ER = (реакции + репосты + комментарии) / просмотры, ERR = (реакции + репосты + комментарии) / подписчики. Для каждого поста сервис добавляет обычные формулы в соответствующие ячейки Google Sheets. Существующие значения и пользовательские формулы сохраняются. При нулевом знаменателе таблица покажет ошибку деления. ID поста, время сбора, возраст и ключ дедупликации записываются в скрытые столбцы. Если сбор опоздал более чем на пять минут, фактический возраст отображается в примечании к просмотрам.

Буквы столбцов настраиваются в YAML. Для нескольких каналов можно задать разные листы; при записи в один лист настройки должны совпадать. Укажите существующие столбцы и лист. Сервис меняет шапку и форматирование настроенных столбцов, не очищает данные; удалите старые строки самостоятельно до смены раскладки. Для старых снимков, ожидающих отправки, обновляется раскладка того же листа, но показатели сохраняются. Если снимок уже зарезервировал строку в старой раскладке, сервис остановится для проверки.

## Как работает сбор

История опрашивается каждые `poll_seconds`. При первом запуске читаются последние `initial_lookback_hours`, затем пропущенные посты восстанавливаются по курсору SQLite. Показатели снимаются в момент фактического сбора, поэтому после простоя они могут отличаться от показателей ровно через 24 часа. Число подписчиков берётся в момент сбора. Удалённые посты не записываются.

Реакции суммируются по типам. Для альбома для каждого счётчика берётся максимум среди элементов, чтобы не умножать повторяющиеся показатели. Снимок сохраняется до отправки в Google Sheets и при ошибке доставляется повторно без повторного сбора. Ключ поста и резервирование строк защищают от дублей после сбоя. Используйте один процесс с одной постоянной базой; другие программы не должны одновременно писать в те же строки. Очищение таблицы не сбрасывает статус уже обработанных постов в SQLite.

```powershell
.venv\Scripts\python -m unittest discover -s tests -v
```
